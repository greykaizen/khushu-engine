# v1.11 Zakat Design — Five Deferred Topics (second source pass + independent cross-check)

Supersedes the §Source-pass section of `docs/v1.3-zakat-design.md` for these
five topics: **debt, shares, mixed irrigation, jewelry valuation, fitr
cash-vs-food**. Research collected 2026-08-28 (fatwa-grade primary sources)
and independently cross-checked against a second reviewer (GPT), which caught
two material corrections — both re-verified here against primary sources.
**Gate unchanged:** knowledgeable-reader review of the §Decision table, then
code. Nothing in this file is implemented yet.

## What the cross-check corrected

1. **Mixed irrigation: 7.5% is NOT the Hanafi position.** Classical Hanafi
   rule is *predominance* — al-Mawsili, *al-Ikhtiyar* (SeekersGuidance Hanafi,
   U. Salman Younas, checked by S. Faraz Rabbani, 2022): "irrigated naturally
   and by human watering, one considers that which predominates." The 7.5%
   average is a modern calculator convenience (myzakatcalc). Predominance is
   the madhab default; proportionality/7.5% survives only as an explicitly
   labeled alternative.
2. **Hanafi debt: intra-madhab conflict, both sides sourced.**
   - IslamQA Hanafi #117950 (IslamicPortal): default position = deduct both
     short- and long-term debt.
   - Daruliftaa.com #8395 (Mufti Muhammad ibn Adam): "the preferred opinion in
     the Hanafi School is that only short-term loans will be deducted and not
     the long-term loans… restrict it to only that payment which is immediate"
     — citing *Radd al-Muhtar* 2/260–261 for both the general subtraction rule
     and the short-term restriction.
   - Engine must expose both as named policies; never silently pick one.
   - The "deduct 12 months of installments" rule is a contemporary
     application, not a universal ruling — no hardcoded universal default.
3. **Receivables: Hanafi tripartite classification is the standard doctrine.**
   Strong (loans, trade proceeds) / medium (non-trade property proceeds) /
   weak (mahr, inheritance claims) — *Radd al-Muhtar*, *al-Mabsut*, *Fatawa
   Qadikhan*. A binary recoverable/unrecoverable model is inadequate; recovery
   of a previously-hopeless debt can revive zakat depending on classification.
4. **5 wasaq = ~653 kg is a modern measured conversion, not revealed text.**
   Classical measure: 5 awsuq = 300 saʿ (volume). Store the kg conversion as a
   documented constant with provenance, never as a bare magic number.
5. **Jewelry: classical principle is *realizable value*** (what you could sell
   it for at zakat date); the jeweler's buyback quote is today's practical
   input for it — not a separate formula (SeekersGuidance Hanafi, S. Faraz
   Rabbani, June 2026, citing Ibn ʿAbidin *Radd al-Muhtar*; retail price
   includes craftsmanship/markup and is excluded).
6. **Shares: AAOIFI Standard 35 permits estimation** when exact company
   zakatable-asset figures are unavailable — the engine needs an explicit
   estimation mode, not only exact look-through.
7. **Fitr cash:** confirmed — majority (Shafiʿi/Maliki/Hanbali per al-Nawawi,
   *al-Majmuʿ* 6/113) require food; Abu Hanifa + Abu Yusuf permit value;
   precedents al-Hasan al-Basri, ʿUmar ibn ʿAbd al-ʿAziz, Abu Ishaq
   al-Sabiʿi (Egypt Dar al-Ifta #7716); Ishaq ibn Rahawayh/Abu Thawr permit
   only in necessity; Ibn Taymiyyah permits for need/maslahah.

## User-input / engine-compute split

The engine never fetches prices. Hosts collect market facts; the engine applies
fiqh-parameterized formulas (consistent with v1.10's `AssetKey`/`notes`
provenance pattern):

| Subsystem | User/host inputs | Engine computes |
|---|---|---|
| Debt | liabilities + each one's immediate-due portion; madhab/methodology | deduction per policy; floored base; nisab comparison; notes with citation |
| Receivables | amount, tier, collectability, receipt date if recovered | inclusion/deferral per policy; past-years accumulation facts |
| Shares | quantity, year-end market value, zakatable portion (per-share or fraction) OR currentAssets/marketCap, intent | basis per intent; dividends folded as cash; 2.5% on basis |
| Ushr | harvest value or weight, irrigation fact (natural/artificial/which predominates, or ratio), nisab policy | rate per policy; wasaq threshold check; gross-value basis; per-harvest due date |
| Jewelry | weight, karat, realizable price per gram (user's jeweler quote, avg of quotes) | pure weight; value; 2.5% |
| Fitr | household size, staple-food unit price (for cash mode), saʿ convention | food quantity per person; cash equivalent; position note |

## API sketch (additive, v1.11.0)

```kotlin
enum class DebtTreatment {
    IMMEDIATE_ONLY,     // preferred Hanafi (Radd al-Muhtar 2/261 via #8395)
    ALL_DEBTS,          // alternate Hanafi (#117950)
    HIDDEN_WEALTH_ONLY, // Maliki
    NONE,               // Shafi'i relied-upon
}

enum class DebtStrength { STRONG, MEDIUM, WEAK }

data class Liability(val amount: Double, val immediatePortion: Double = amount)
data class Receivable(val amount: Double, val strength: DebtStrength,
                      val recoverable: Boolean)

enum class ShareIntent { TRADING, LONG_TERM }
enum class ZakatableBasisSource { EXACT, ESTIMATED, CONSERVATIVE_FULL }
data class ShareHolding(val shares: Int, val marketValue: Double,
                        val intent: ShareIntent,
                        val zakatablePortionFraction: Double? = null,
                        val basisSource: ZakatableBasisSource = ...)

enum class Irrigation { NATURAL, ARTIFICIAL }
enum class MixedIrrigationRule { PREDOMINANT, PROPORTIONAL }
enum class UshrNisabPolicy { NO_NISAB, FIVE_WASAQ }

enum class JewelryValuationBasis { REALIZABLE_VALUE, MARKET_RETAIL }
enum class FitrPaymentMode { FOOD, CASH_EQUIVALENT }
```

- `ZakatParams` gains `debtTreatment: DebtTreatment?` (null = madhab default),
  `mixedIrrigationRule`, `ushrNisabPolicy` — all nullable-overridden, all
  emitted into `ZakatResult.notes` with citation strings when non-default.
- `ZakatRules.ushr(...)` gains the mixed/nisab overloads; existing single-rate
  ushr API unchanged.
- Fitrana gains `mode` + staple-price input; existing signature stays.
- Store: `ZakatSettingsDto` gains the same fields **with defaults** — no
  schema-version bump; codec leniency (unknown keys ignored, missing fields
  default) already covers both upgrade directions.

## Non-goals (unchanged)

No live price fetching, no fatwa issuance, no recipient-eligibility decisions,
no silent madhab resolution. Disputed cases the engine won't settle keep the
`RequiresScholarReview` escape hatch from the v1.3 principles.
