# v1.16 Tasbih + Observance Design — streaks, tasbih, bookmarks, reading, khatm

Status: DECIDED 2026-08-31 — implementation in flight. This document is the
locked design (decisions + reasoning + API contract); the code follows it.

Unlocks roadmap §8 of the Khushu plan (`docs/plans/settings-ux-roadmap.md`):
`readStats` / `khatmFacts` / `dhikrStats` were parked there as gated
engine-side computations; this release is that gate opening, plus the
centralized-bookmarking and tasbih asks.

## Decisions (each reasoned, locked)

### D1. Tasbih presets: ENGINE-SEEDS (minimal, provenance-cited)
Canonical devotional conventions have always shipped in-engine
(`Convention.MUSLIM_WORLD_LEAGUE`, calendar `builtInDefinitions`) — they are
rules with fiqh sources, not corpus content. The lifewithallah dua corpus in
data-api remains the EXPANSION path via factories (`ofDua`/`ofName`). Seeds:

| Preset | Target | Source (KDoc-cited) |
|---|---|---|
| SubhanAllah / Alhamdulillah / Allahu Akbar | 33/33/34 | Muslim #597 (post-prayer set) |
| Istighfar (Astaghfirullah) | 100 | Tirmidhi / Abu Dawud |
| Salawat | 100 | Muslim #408 |
| Tahleel (La ilaha illa Allah) | 100 | Tirmidhi |
| SubhanAllahi wa bihamdihi | 100 | Bukhari ("two phrases light on the tongue") |

(7 seed definitions — the post-prayer triple counts as three presets, one per dhikr.)

Presets prefill `targetCount` only; `dailyGoal` stays null — the engine never
invents goals (user sets them host-side).

### D2. TWO new modules: `engine/tasbih` + `engine/observance`, both → core
Real domain boundary: tasbih owns counting nouns (definitions/counts/goals);
observance owns reading/bookmark/khatm nouns. A Quran-reader host can take
`engine-observance` without tasbih and vice versa. Graph stays flat/acyclic;
the publish gate keys on `:engine:*` so JitPack picks both up automatically.

### D3. Prayer delegation to the shared core math: PARKED to 2.0.0
Prayer's loop is not actually generic (applicable-set semantics, domain-typed
rates); the shared residue is ~30 lines. Touching a locked module guarded by
a 6,184-case golden matrix to save that is negative-value churn. The 2.0.0
cleanup inventory gains: "prayer.streakStats delegates to core DayStreakMath".

### D4. khatmFacts: host-supplied tables, parameterized totals
Juz ranges and surah boundaries are textual data of a mushaf arrangement —
data-api already exports both (`quran_metadata/ayahs.json`: 6,236 rows with
ayah_id/surah/juz columns; `navigation_ranges.json`: juz → ayah ranges).
Engine carries NO second copy (duplicate-implementation sin + sync burden).
One documented constant follows the `FIVE_WASAQ_KG` precedent:
`TOTAL_AYAHS = 6236` as the parameterizable default.

### D5. STRICT streaks everywhere + excusedRanges everywhere
Consistency across domains is a correctness requirement, not aesthetics —
mixed policies mean the same missed day breaks reading but spares tasbih,
which users cannot reason about. Critical distinction carried by the core
math: **excused ≠ grace.** Excused ranges (travel/illness/menses — host
declared) pass through all domains exactly like prayer's. Grace/streak-freeze
(engine-invented excuse) exists nowhere.

## Architecture (non-negotiable, same doctrine as prayer observance logs)

```
HOST LOGS events → host Room/DataStore (source of truth; engine persistence-free)
ENGINE COMPUTES facts over caller-supplied logs (streaks/progress/khatm/continue)
SUPABASE (Khushu) MIRRORS the logs — never the derived facts
```

Refs (`"2:255"`, `"bukhari_urn_100010"`, `"dua_47"`, `"ar-rahman"`) are
OPAQUE to the engine. Content validation ("does 2:255 exist?") happens at
creation time via data-api; the engine validates shape and does the algebra.

## Module contract

### core/observance/DayStreakMath (new core namespace)
```kotlin
data class DayClass(val complete: Boolean, val excused: Boolean)
data class StreakFacts(
    val currentStreakDays: Int, val longestStreakDays: Int,
    val completedDays: Int, val excusedDays: Int, val spanDays: Int,
)
fun dayClasses(first, last, isComplete: (LocalDate) -> Boolean,
               excusedRanges: List<ClosedRange<LocalDate>>): List<DayClass>
fun streakFacts(days: List<DayClass>): StreakFacts
// Contract mirrors prayer's documented day semantics verbatim:
// complete-or-excused extends; silent/uncompleted BREAKS; excused is neutral;
// span bounded by first..last logged dates.
```

### engine/tasbih
```kotlin
enum class TasbihSource { PRESET, DUA, ASMA_NAME, CUSTOM }
data class TasbihDefinition(
    id, name, arabic: String?, targetCount: Int,
    dailyGoal: Int? = null,          // null = freeform (no streaks, totals only)
    source: TasbihSource = CUSTOM, sourceRef: String? = null,  // duaId / name number
)
data class TasbihCountLog(definitionId, date, count)

object Tasbih {
    val PRESETS: List<TasbihDefinition>                       // D1 seeds
    fun ofDua(duaId, name, arabic, targetCount): TasbihDefinition
    fun ofName(nameNumber, name, arabic, targetCount): TasbihDefinition
    fun custom(id, name, targetCount, dailyGoal?): TasbihDefinition
    fun progressToday(logs, definition): Int                  // summed per date
    fun dhikrStats(logs, definitions, excusedRanges): List<DhikrStats>
    // DhikrStats: todayCount, goalMetToday, goalStreak (STRICT via core),
    // lifetimeTotal, lastCountedDate
}
```
Host flow ("dua/dhikr/names → select → create tasbih"): Khushu queries
`content.dua.bySubcategory(...)` / `asmaName(...)` → `Tasbih.ofDua/ofName`
→ appends to its Room list → logs counts against it.

### engine/observance
```kotlin
// Bookmarks — centralized algebra for ALL domains (no per-mod/host systems):
enum class BookmarkDomain { QURAN, HADITH, DUA, ASMA_NAME, ARTICLE, CUSTOM }
data class Bookmark(domain, ref, label? = null, anchor? = null, createdAtEpochMs)
fun toggle(bookmarks, domain, ref): List<Bookmark>   // add/remove/dedup
fun upsert(bookmarks, candidate): List<Bookmark>     // anchor/label merge;
                                                      // createdAt PRESERVED
fun byDomain / recent / grouped                       // list-in → view-out

// Reading (roadmap §6/§8 implemented):
data class ReadingSession(domain: QURAN|SUNNAH|DUA|ARTICLE, ref, openedAt,
    secondsActive: Int, versesViewed: Int? = null, completedToday: Boolean = false)
data class ReadingTarget(domain, ayahsPerDay? = null, minutesPerDay? = null)
fun readStats(sessions, targets, excusedRanges): ReadStats
    // per-domain: todayProgress vs target, todayMarked, STRICT streak
    // (over explicit-mark days only — scroll-past never completes),
    // totals, lastRead
fun continueReading(sessions): Map<ReadingDomain, ReadingSession>  // RANK-1
fun history(sessions, window: WEEK|MONTH): ReadingHistory           // Profile feed

// Khatm (Rank-2 math; zero content in engine — D4):
data class AyahRange(startAyahId, endAyahId)
data class JuzRange(juz, range: AyahRange)
fun khatmFacts(completed: List<AyahRange>, juzRanges: List<JuzRange>,
               totalAyahs: Int = TOTAL_AYAHS): KhatmFacts
// coveredAyahs, progressFraction, normalizedRanges (sorted/coalesced),
// currentJuz, remainingAyahs, projectedCompletionDate (rate inputs or null)
```

## Wiring
- Facade: `engine.tasbih.*` + `engine.observance.*` pure-delegation namespaces
- `settings.gradle.kts` + module builds (`api(project(":engine:core"))` so
  facade sees types) + BCV api files
- Store: UNTOUCHED (user observance data ≠ settings — doctrine holds)
- AGENTS: module rows, dependency line (`tasbih/observance → core`), 2.0.0
  inventory +1 (D3)
- Release: v1.16.0 tag carries the untagged localOffsetDays store commit
